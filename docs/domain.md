# Domain

## Domain Overview

1チームの少年野球クラブを対象とする。チームには選手（子）と、選手に紐付く保護者、指導者が所属する。チームは練習・試合などのイベントを登録し、イベントごとに出欠を集める。

## Terminology

| Term | Meaning |
|---|---|
| Player（選手） | チームに所属する子。出欠の対象。 |
| User（メンバー） | アプリ利用者。保護者 / 指導者 / 選手のいずれかの立場を持つ。 |
| Parent（保護者） | 1人以上の Player に紐付く User。父・母それぞれが別 User。 |
| Coach（指導者） | イベントを作成し、全員の出欠を閲覧・修正できる User。 |
| Event（イベント） | 練習 / 試合 / その他。日付・時間・場所を持つ。 |
| Player Attendance | Event × Player の出欠。1件のみ存在する。 |
| Member Attendance | Event × User の参加（保護者の帯同・お手伝い）。 |
| Invite Code（招待コード） | Player ごとに発行される参加コード。指導者・スタッフ用にはチーム共通コードを持つ。 |

## Business Rules

- Player（選手名簿）の登録は指導者のみが行う。名簿はチームの資産として扱う。
- 保護者・選手本人は招待コードで既存の Player に紐付く。自分で Player を作成できないため、同じ子が重複登録されない。
- 1人の Player に複数の Parent が紐付く（父・母が同じ招待コードを使う）。
- Player の出欠は Event × Player で一意。父・母どちらが回答しても同じ1件を更新し、最後に更新した User を記録する。
- 保護者本人の参加（帯同）は選手の出欠とは別に記録する。
- 出欠は「出席 / 欠席 / 未定（未回答）」の3状態。未回答は未定として扱う。
- 指導者は全選手の出欠を閲覧・修正できる。保護者は自分に紐付く Player のみ修正できる。
- 選手 User は自分自身の Player に紐付く。

## Important Constraints

- 選手本人がアカウントを持っても持たなくても成立するデータモデルにする（出欠は Player に紐付き、User には紐付けない）。
- 選手本人のアカウントも保護者と同じ招待コードで後から追加できる。

## Unknown Rules

- 出欠の回答期限、締切後の変更可否
- 遅刻・早退など部分参加の扱い
- 配車・当番など保護者の役割割り当ての要否
- 指導者による代理修正の許容範囲
- 招待コードの有効期限・再発行・不正利用対策
- 退団・卒団時の Player とアカウントの扱い
